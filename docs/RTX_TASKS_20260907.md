## 2. OG 4채 생성 — 1200프레임, SPEC 4-4 게이트, 매핑워크 보행 프레임 포함
씬 4개: `Rs_int` · `Pomaria_1_int` · `Merom_1_int` · `Wainscott_0_int` (og_gen20.sh 의 통과 씬 중 앞 4개. 손에 있는 다른 4채여도 된다).
```bash
WORK=/mnt/ssd2/wooyeol/work; PY=$WORK/behavior1k_latest/conda_envs/behavior51/bin/python; OG4=$WORK/og4; mkdir -p $OG4
export OMNI_KIT_ACCEPT_EULA=YES OMNIGIBSON_GPU_ID=1 OMNIGIBSON_HEADLESS=1 PYTHONNOUSERSITE=1
export OMNIGIBSON_DATA_PATH=$WORK/behavior1k_latest/og_data_2026 OMNIGIBSON_APPDATA_PATH=$WORK/behavior1k_latest/appdata_og51
i=0; for SC in Rs_int Pomaria_1_int Merom_1_int Wainscott_0_int; do H=$OG4/house_$(printf %04d $i)
  grep -q EPISODE_OK $H.log 2>/dev/null || $PY -u scripts/og_episode.py --scene $SC --out $H --house $i --frames 1200 --props 24 \
      --case1 10 --case2 5 --case3 5 --case4 0 --map-sites 3 --map-travel 0.35 --map-step 45 --seed 0 > $H.log 2>&1
  echo "$SC $(grep -c EPISODE_OK $H.log) map=$(ls $H/map/*.jpg 2>/dev/null | wc -l) live=$(ls $H/live/*.jpg 2>/dev/null | wc -l)"; i=$((i+1)); done
```
- 성공 판정은 `EPISODE_OK` 마커다(종료코드 139 는 정상). 게이트(moving ≤0.6 · room_switches ≤30/1200) 표는 로그의 게이트 줄 5개를 그대로 보고.
- **매핑워크에 지점 사이 보행 프레임(0.35 m 간격)이 들어가야 한다.** `--map-travel 0.35` 가 그것이다. 지도 250~500장이 정상. 회전만 있는 지도는 어떤 모델도 못 세운다.
- 4채가 안 되면 되는 만큼(2채)으로 §3 을 시작해도 된다. 스크립트는 있는 채만 돈다. **20채 생성은 하지 않는다.**
- 입력 요건(스크립트가 읽는 것): `map/%04d.jpg` ↔ `gt.json["map"][i]`(`apos=[x,z]`·`yaw`·`room`), `live/%06d.jpg` ↔ `gt.json["live"]` 의 `t`, `gt.json["rooms"]` 폴리곤. `og_episode` 출력이 이미 이 형식이다.

## 5. 읽는 법과 기준선
- `[진단] sim3 정렬(… 인라이어 X …)`: **X ≥ 0.4 이면 지도가 섰다**, <0.2 는 접힘. ATE 중앙 ≤0.5 m.
- `[실제] … 카메라방 적중 Y`: **Y ≥ 0.8 이면 채택선**(임베딩 카메라방의 0.81 과 같은 급).
- 나란히 볼 기준선: HSSD 에서 COLMAP 스캔 지도는 30채 중 1채(§163), 촘촘한 지도로도 4채 중 1채(§164). GT 스캔 포즈 지도 + 1fps PnP 는 등록 0.54~0.73·<0.5 m 0.6~0.99(§166-13).
  실사 Nymeria 는 COLMAP 스캔 지도 + PnP 등록 0.70·<0.5 m 0.85(§166-5). OG 에서 VGGT/CUT3R 가 ≥0.4 를 내면 "시뮬 스캔 GT 를 학습식으로 대체" 갈래가 열린다.
