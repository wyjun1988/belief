## 감사 게이트 (`scripts/audit_export.py`)

```
A. counts: {frames: 965, poses: 965, rgb: 965, gt/seg: 965, gt/depth: 965}
B. pose step  median 0.0134 m   max 0.1046 m
C. proj err   n=999  median 3.1 px  p90 17.1 px
D. depth rel err  median  z:0.021  range:0.151  → z-depth 관례
PASS
```

C 는 GT 3D 중심을 우리 선형 K·`T_world_camera` 로 투영한 픽셀과 GT 마스크 무게중심의
거리다. **중앙값 3.1px** 은 어안→선형·cw90 회전·`T_device_camera`·GT 포즈가 한 줄로
맞물린다는 뜻이다. D 는 덤으로 **ADT GT 뎁스가 사거리가 아니라 z-깊이 관례**임을 확정했다.

## 잡은 함정 3건

1. **VRS 가 GT 보다 먼저 시작한다** — party 365프레임(12.2s), decoration 230프레임.
   자르지 않으면 provider 가 경계값으로 클램프한 포즈를 *경고만 찍고* 돌려준다.
   10Hz 기준 앞 100여 프레임이 통째로 오염될 뻔했다. → `export.py:_uniform_indices`
   가 `[get_start_time_ns, get_end_time_ns]` 로 먼저 자른다.

2. **앵커 셀 축약을 최근접으로 하면 정반대가 된다** — 값싼 z-버퍼로 셀마다 가장
   가까운 앵커를 남겼더니 앵커/GT 뎁스 비율이 0.31~0.54 로 내려앉았다(46% 오차).
   반-조밀 포인트는 표면을 다 덮지 않으므로 "가장 가까운 게 보이는 표면"이라는 전제가
   성립하지 않고, 노이즈 근접점 하나가 셀을 대표해버린다. **셀 중앙값 + 깊이폭 기반
   셀 기각**으로 바꾸자 비율 0.98→1.00, GT ±10% 인라이어 24%→**65%**.

3. **Huber + 절대 잔차 조합이 '깊이 일정' 퇴화해로 수렴한다** — 두 가지가 겹쳤다.
   (a) 역깊이 **절대** 허용오차는 가까운 앵커를 전부 이상치로 만들고 먼 점만 맞추는
   평평한 해(a≈0.03)에 최고점을 준다. (b) 가림 앵커는 언제나 *더 멀어서* 잔차가
   **편측**인데 Huber 는 재하강하지 않아 계속 끌려가고, 적응 스케일이 0.04→0.61 로
   폭주하며 이상치를 전부 인라이어로 흡수한다. RANSAC 은 정답(a=0.92)을 찾아놓고도
   IRLS 첫 스텝에서 무너졌다. → **상대 잔차 + Tukey 재하강 + 스케일 상한 2%**.

## 정합 자체검증 (`scripts/selftest_align.py`)

GT 뎁스에 윈도우별 affine(scale σ=0.08, shift σ=0.02, stride 12)을 주입해 DA3 의
윈도우 드리프트를 흉내 낸 뒤 복원시킨다. 150 연속 프레임:

| | AbsRel |
|---|---|
| 주입 후(정합 전) | 0.0688 |
| **T2 (앵커 affine)** | **0.0026** |
| T2+T3 λ=0.5 | 0.0070 |
| T2+T3 λ=2 | 0.0097 |
| T2+T3 λ=20 | 0.0158 |

앵커 자체의 GT 대비 오차는 프레임 중앙값 2.6%, p90 5.4% (프레임당 앵커 3,854개).

**해석**: 앵커가 충분한 프레임(여기서는 150/150 전부)에서는 T2 만으로 사실상 완전
복원되고 **T3 는 손해**다. T3 의 존재 이유는 앵커가 빈곤한 프레임(근접·저텍스처·역광)의
보간과 프레임별 적합 잡음 억제이지, 잘 관측된 프레임을 평활하는 게 아니다. 이 근거로
기본 λ 를 20 → **1.0** 으로 내렸다. **T3 의 값어치는 실제 DA3 출력에서 재확인해야 한다**
(합성 실험은 적합 잡음이 없어 T3 에 불리하게 편향돼 있다).
