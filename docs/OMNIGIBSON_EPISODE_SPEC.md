**요약**: 지금 생성 중인 판은 **평가에 못 쓴다.** 우리 파이프라인이 요구하는 필드와
구조가 THOR/HSSD 이식 과정에서 확정됐는데(2026-08-31~09-02), 그게 반영 안 됐다.
아래 5개를 반영해 다시 생성할 것. 각 항목은 **실측으로 물린 것**이라 생략하면
수치가 조용히 거짓이 된다.

## 1. 시나리오는 **대본**으로 (무작위 생성 금지) ⚠️ 가장 중요

지금까지 배회·이동을 확률로 굴리고 사후에 표본 수를 셌다. 그 결과 **경우③ 이
240건 강제해도 4건**(THOR), **21→13건**(HSSD)으로 판정 불가였다.
채당 아래를 **보장**하도록 궤적과 이동을 설계할 것:

| 경우 | 채당 목표 | 보장 방법 |
|---|---|---|
| ① 이동 없음 | ≥10 타겟 | 안 움직인 물체 중 재방문 있는 것 |
| ② 이동+재촬영 | **≥5건** | 이동 후 **그 방으로 궤적을 보내** 2m 이내 3프레임+ 목격 |
| ③ 부재→belief | **≥5건** | 이동 후 새 방 **미방문** + 옛 방 재방문 **보장** |
| ④ 집 밖 반출 | ≥2건 | outdoor/garage/porch 로 이동, 이후 실외 미방문 |

**이동 물체는 타입이 그 집에 하나뿐인 것**만(혼동 회피 — 우리 과제 정의).

## 2. 길이: 최소 1,200프레임 (THOR 4시간 = 14,400 이 이상적)

400프레임 판에서 **이동 후 진짜 크롭이 1,100장 중 14장**뿐이라 ② 측정이 불가능했다
(A율 84%). 1,200 으로 늘려 A 57%·② 0.176. **200프레임은 측정 자체가 성립 안 한다.**

## 3. 매핑워크 필수 — 없으면 이동 물체가 평가에서 통째로 빠진다

> **밀도 (2026-09-03 추가)**: 초기 등록은 일회성이라 **무겁게** 가도 된다. 방당 지점 1개·6방향은
> 시점이 하나라 겹침이 없고, 그 결과 ① 오답의 대부분(작은 물체 미검출·오검출의 투영)이 여기서
> 났다. 요구: **방당 ≥3 지점(서로 ≥1.5m, 최원점 샘플링) × 45° 8방향** = 방당 24장 이상.
> 초기맵은 서로 다른 지점 2곳 이상에서 같은 자리로 투영되는 검출만 등록한다(`INITMAP_MINVIEWS=2`).
> `og_episode --map-sites` 를 3 이상으로.

에피소드 시작 전 **방마다 들러 6방향(0/60/…/300°) 스캔**. 이 프레임에서 물체
exemplar 를 뽑기 때문에, 매핑워크가 집 전체를 못 돌면 그 물체는 타겟 목록에서
누락된다(HSSD 1차 실패 원인). `map[]` 에 **apos·yaw·ctr·dist 까지** 남길 것 —
초기 씬그래프를 투영으로 구축하는 데 필요하다(방배정 0.32 → 0.78).

## 4. GT 정직성 3종 (전부 실측으로 물린 것)

1. **이동 목적지는 실제 좌표로 재판정**하라. "방 중심 근처 배치" 는 옆방으로
   넘어간다 — HSSD 에서 **31% 오염** 실측. 옮긴 뒤 좌표로 방을 다시 구해 `to` 에 기록.
2. **가시성(vis)을 거리로 자르지 마라.** THOR 기본 1.5m 가 GT 를 오염시켜
   물체당 보인 프레임이 6장 대 122장으로 갈렸다(§58). 12~20m 로 열고, 대신
   **가림 검사**(depth 와 투영 깊이 일치 ±0.6m)로 거른다.
3. **연속 보행 궤적**(텔레포트 금지). SfM/VO 포즈 사슬이 성립하는 유일한 조건이다.
4. **이동 물체는 받침면 위에 실제로 놓아라**(§125). x·z 만 바꾸고 높이를 두면 가구 속에
   박혀 렌더에 없는데 GT 는 "보인다" 고 한다 — HSSD 에서 두 달간 ② 가 0 이었던 원인.
   생성 후 **이동 물체의 이동 후 검출률 = 이동 전 검출률** 을 확인하고, 이동마다
   증인 렌더(새 자리 2m 앞)를 저장할 것. GT 좌표는 배치 후 시뮬에서 다시 읽은 값.

## 4-2. 2026-09-02 추가 — HSSD 에서 실측으로 물린 것 (§125·§128)

1. **매핑워크는 이동 전에** 돌려라. live 루프 뒤에 돌리면 이동 물체의 exemplar 가 빈자리 크롭이
   된다 (HSSD 맵 박스 OWL 적중 0.25 → 고친 뒤 0.58).
2. 물체 좌표는 **렌더되는 것의 중심**(rigid COM / bbox center)으로. 인스턴스 원점(자산 로컬
   원점, 바닥)과 최대 1.3m 다르다. 이동 배치에서 두 규약을 섞으면 물체가 반 높이 파묻힌다.
3. 가시성은 **카메라→물체 레이캐스트**(첫 충돌이 그 물체인가). 중심 픽셀 depth 비교는
   가구 속에 박힌 물체를 "보임" 으로 통과시킨다.
4. 저장하는 **모든 좌표 필드**(gt0·moves·live·map·static·polys)가 같은 규약인지 필드별로
   확인하라 — 폴리곤 포함률로 잰다 (HSSD: moves.pos·static.pos 만 미러가 빠져 있었다).
5. 방 라벨은 **점-폴리곤**(겹치면 면적 최소). AABB 는 겹치는 방에서 사전 순으로 틀린다
   (물체 13%·프레임 17% 오라벨).
6. 이동마다 **증인 렌더**(새 자리 2m 정면) + **받침 검사**(COM 아래 첫 충돌이 오프셋 근처)를
   저장·통과시켜라. 실패한 이동은 원위치로 되돌리고 기록하지 않는다.
7. 검출기 self-test: 이동 물체의 **이동 후 검출률 ≈ 이동 전** (`scripts/gen_selfcheck.py` 참조).
8. 평가는 **증거 조건부**(docs/EVAL_PROTOCOL_V2.md). 생성기에 `--evidence K:D`(거리 D 시선
   지점 K 회 방문, 물체를 보며 진입) 와 `--case3`(목적지 저체류·최원 방 + 경유·시선 누출 경로
   재추첨) 에 해당하는 대본 장치를 넣어라. 무작위 배회로는 ③ 이 0 건이다.

## 4-3. yaw 규약 (2026-09-02 검토에서 확정)
내보내는 `yaw` 는 **bearing = atan2(dx, dz)** 규약이다: 0° = +z(=og_y), 시계 방향 증가,
β(앵커) = yaw + atan((u − cx)/fx). OG 내부 θ(0°=+og_x, 반시계)와는 미러 없이 **yaw = 90° − θ**
로 일치한다(합성 검증 0°). `og_episode.py` 가 내보내기 직전에 변환하고 `yaw_og` 를 함께
남기며, `scene_meta.yaw_audit_ours` 로 **우리 공식 기준 0.5° 게이트**를 건다.

## 4-4. 보행 사실성 (2026-09-03, 검수 영상 지적: "같은 공간을 쉬지 않고 계속 돌고, 너무 빠르다")

궤적이 **쉬지 않는 배회**면 재방문 패턴·속도감·목격 분포가 전부 비현실적이다. 실제 생활은
대부분 **머무름**이고 이동은 목적이 있는 짧은 구간이다. 요구:
1. **체류**: 목적지 도착 후 방 체류 가중에 비례한 시간(평균 20~40 프레임, 지수분포) 제자리 체류.
   체류 중 고개 스캔 ±30~40°(사인). 1200 프레임 중 체류 비율 ≥ 50%.
2. **완보**: 이동 구간 0.25 m/프레임(1fps 기준 0.25 m/s = 둘러보며 걷는 속도) 이하.
   회전 평활 계수 0.3~0.4(프레임당 목표각의 30~40% 접근), 최대 회전 25°/프레임.
3. **방 전환 빈도**: **체류 목적지 변화** 기준 ≤ 30회/1200 프레임 (2026-09-03 RTX 실측으로 정의 확정:
   프레임 단위 방 라벨 변화는 개방형 평면에서 한 번 이동에 중간 방 2~3개를 지나 2.1배 부풀려진다 —
   161 vs 75). 프레임 단위 원값은 `room_switches_raw` 로 병기하되 게이트는 목적지 기준.
   ⚠️ 이 게이트를 맞추려고 `--evidence` 를 줄이지 말 것 — ② 증거(k)가 줄어든다. 필러 체류 길이로 줄인다.
4. 검수 영상은 1fps 원본을 10fps 로 재생하면 10배속임을 캡션에 적을 것 — 속도 판단은
   `moving_frame_frac`(≤0.5)·`room_switches`·`mean_dwell_frames` 숫자로 한다.
`hab_episode --dwell 30 --pace 0.25 --turn 0.35 --scan 35` 가 HSSD 쪽 대응 구현.
5. **NaN 물체**: 물리 발산으로 AABB 가 비유한이 된 물체는 live/gt0 에서 함께 제외하고 `audit.nan_dropped` 에
   기록. **이동 대상 물체가 NaN 이면 그 이동은 롤백·미기록**(조용히 사라진 이동 물체는 ②③ 표본을 오염).
   게이트: `nan_dropped ∩ moves.oid = ∅`.

## 5. 좌표 규약 — 이 한 줄로 검증하라

생성 후 반드시:
```
프레임의 정적 앵커(지도 좌표 + 화면 x)로 yaw 를 역산해
기록한 yaw 와 비교 → **오차 중앙값이 0°** 여야 한다.
```
habitat 은 화면 오른쪽이 방위각 **감소**(왼손) 라서 x 미러 + yaw 부호 반전이
필요했다(§120). Isaac/OmniGibson 도 규약이 다를 수 있으니 **숫자로 닫을 것.**
1°만 어긋나도 투영 국소화가 0.97 → 0.25 로 무너진다.

## 6. 시나리오 사전확률 (선택이지만 권장)

배회·이동을 균등 난수로 두면 (a) 재방문 패턴이 비현실적이고 (b) 목적지가 균등이라
belief 가 원리적으로 못 맞힌다(§67). `data/hssd_move.json` 과 같은 형식으로
OmniGibson 어휘용을 만들면 된다 (`scripts/hssd_move_llm.py` 재사용, 어휘만 교체):
```
{"dwell": {방유형: 상대체류}, "mobility": {물체: 0~1}, "dest": {물체: {방유형: 확률}}}
```

## 7. OmniGibson 고유 이점 — 반드시 살릴 것

이 도메인을 고른 이유는 **문·서랍·수납장 상태**를 시뮬한다는 것이다:
- 경우③ 의 자연스러운 제조: "서랍에 넣었다" = 이동 후 안 보임이 물리적으로 성립
- 문을 닫으면 옆방 물체가 시야에서 빠져 **"보이는 방 ≠ 있는 방"** 오염이 줄어든다
`--case3` 대응 장치로 **수납 이동**(물체를 서랍/캐비닛 안으로)을 우선 쓸 것.
