# 기술 정리 — 2026-08-26 (실측 기준)

## 1. Scene graph 생성 (초기 맵 — 한 번만, 무겁게 허용)

**촬영**: 매핑워크 — 사람이 새 집을 둘러보듯 걷는 연속 궤적. 걸음 0.25 m,
방마다 주기적 360° 스캔, 채당 ~1,000프레임. 이 단계만 pose·depth 허용
(실배포: DA3 mono-depth + SfM / 시뮬 검증: GT — 기하 사슬 역투영 오차 중앙 0.46 m).

**검출기**: OWLv2-base-patch16-ensemble, **155M** (fp32 0.6 GB).
왜 이것인가 — ① 개방어휘 텍스트 질의 ② **한 백본의 패치 임베딩에 세 헤드**
(글자·타겟 exemplar·앵커 개체가 전부 내적만) ③ 이미지-조건 질의 지원.
대형 대안은 실측 기각: OWLv2-large(430M)는 AUC만 오르고 정밀도 하락,
GDINO 는 채점 불가 판정.

**저장물**:
| 산출 | 내용 | 실측 품질 |
|---|---|---|
| 정적 앵커 개체 | 타입·3D 좌표·방 | (방,타입) 정밀 0.4~0.5 · 재현 0.8~0.9 — "부풀린 지도"지만 하류 비용 **−0.02** |
| 물체 exemplar | bbox 최대 프레임의 패치 임베딩 | 프레임 선택 @5 0.895 의 재료 |
| CLIP 방 노드 | 매핑워크 프레임 512d + 방 라벨 | 방 인지 0.964 의 재료 |
| 토폴로지 | 방 폴리곤·문 연결 | scene_meta |

**약점과 개선**: ① 소형물 초기 등록 0.2~0.5 — 걸어 지나가며 연필까지 등록은
원리적으로 무리 → **온라인 첫 목격 등록**으로 이관(실험 중) ② exemplar 가
14px 급 — 맵 촬영에 물체 접근 단계 추가 여지 ③ 실배포 눈금은 DA3 로 재측정 필요.

## 2. 1 fps 촬영 (배회 — 런타임, RGB 만)

**저장하는 것** — 원 latent(패치 임베딩 60×60×512)는 **버린다.** 질의 임베딩과의
내적 결과만 남긴다:

| 항목 | 차원 | 용도 |
|---|---|---|
| 타입별 점수 | ~90 (타겟52+정적38) | 검색·부재 |
| 타겟 exemplar 점수 | 물체 수 | 검색(인스턴스) |
| 앵커 개체 점수+화면위치 | ~60×3 | 국소화·부재 게이팅 |
| CLIP 프레임 임베딩 | 512 | 방 인지(노드 대조) |

프레임당 수 KB — 3시간 채당 캐시 ~1–2 MB. "feature 로 저장"이 맞고, 정확히는
**점수+국소 좌표+전역 512d**다. (라벨·bbox 를 저장하는 게 아니라 질의 가능한
수치를 저장 — 새 질의 어휘가 생기면 재계산 필요하다는 한계도 명시)

**모델·시간**: OWL 155M 1회 + CLIP-비전 86M 1회 = **M1 Max ~1초/프레임**
(1 fps 실시간 성립 — 시뮬 프레임 기준). 타겟 기기(안경)는 미검증 항목:
IMU 안정시 촬영 + 폰/허브 처리 캐스케이드 + int8 이 전제.

**온라인 갱신**: 방 Viterbi 는 스트리밍 DP, 기록 갱신은 장부 갱신 — 비용 ~0.

## 3. QA 질의 (사용자 스케치 대비 정정 포함)

**분기 구조** (실측: (a)0.701 · (b)0.593 · (c)0.420 / 전체 0.68~0.72):

```
0. 확신 목격이 기록과 다른 방 → 그 방      (게이트 신호 부족으로 사실상 미발동 — 현안)
1. 재확인됐거나 확인 못함     → 기록의 방
2. 부재 확인               → belief 로 핸드오프
```

✏️ **"top 20 → LLM 선별"** — 현행이 아니다. 현행은 **글자+exemplar 합산 점수
상위 + 문턱-후-최신**(T1 0.493). LLM(VLM) 선별은 두 번 시험됐다:
다수결 방식(§53)은 실패 확정, **검증기 방식**(후보 ~5장 yes/no)은 슬롯 가치가
크지만(오라클 상한 T1 0.742, 시스템 ~0.84) 4B 가 실사·시뮬 모두 0.60/0.72 로
스펙(0.85/0.85) 미달 — 9B/32B 판정 대기. **즉 "LLM 선별"은 아직 채택 전이다.**

✏️ **"keyword 부재 검출"** — 폐기됐다. 확장질의−키워드는 앵커와 중복(§71).
현행은 **앵커 게이팅 부재**: 자리 서명이 화면에 보이는 프레임에서 물체 점수의
자기보정 하락. 능력 AUC 0.781 / 온라인 0.626 · 게이트 정밀 0.860 · 재현 0.112.

✏️ **"답변이 가능하면 LLM 답변"** — 답변에 LLM 없음. 답은 방 이름이고 분기
규칙이 낸다. **belief 도 런타임 모델이 아니라** Qwen 이 오프라인 생성한 사전확률
JSON 의 argmax 다(천장 0.58 · 핸드오프 후 실측 0.488). 사전확률 천장 위는
관측 조건부 학습 belief(home-jepa)의 몫 — 미통합.

**scene graph 업데이트** — 부분 구현: 부재 발동 시 기록에 "없음" 반영은 평가에
있음. 확신 목격에 의한 기록 갱신(경우 0)은 게이트 신호가 없어 미발동 — T1
27%p 가 여기 걸려 있고, 검증기(위)와 온라인 등록(실험 중)이 그 열쇠다.

## 현재 병목 순위 (손실 회계)

```
1. T1: 새 방 목격을 답으로 전환   27%p  ← 검증기 슬롯 (9B 판정 대기)
2. 소형물 초기 등록 0.2~0.5            ← 온라인 등록 (실험 중)
3. 부재 재현율 0.112                   ← 지렛대 작음 (T2 16건)
4. belief 천장 0.58                    ← 학습 belief 별도 트랙
```

## 부록 — 용어·구분 Q&A (2026-08-26 문답 반영)

- **exemplar**: 씬그래프 구축 때 물체별 최적 프레임에서 뜬 패치 임베딩(벡터,
  수백 B). "머그컵"(글자)이 아니라 "그 머그컵"으로 검색 — @5 0.486→0.793.
- **포즈(실배포)**: DA3 뎁스 + 물체 랜드마크 SfM 보정(`incremental_sfm`·
  `align_depth_sfm`). 시뮬은 GT 로 기하 사슬만 검증(0.46 m).
- **방 나누기 vs 방 노드**: 경계 정의(지도 자르기)는 **미구현·GT** — 실배포 숙제.
  방 노드는 정의된 방마다의 "사진첩"(매핑워크 CLIP 임베딩 묶음) — 인지용 참조.
- **그래프 생성(규칙)**: OWL 검출 → 뎁스 역투영 → 탐욕 군집(0.7 m, 약한 군집
  폐기) → 폴리곤 방 배정 → 노드(개체)+간선(방·문). 학습 모델 없음.
- **방 인지 vs 국소화**: 주어가 다르다 — 카메라의 방 vs 물체의 방. 오픈플랜에서
  일치 0.257 이라 국소화는 앵커(옆 가구)로 별도 해결.
- **재방문 판정**: (b)/(c) 스위치 — 다시 가봤을 때만 부재 주장 자격이 생긴다.
