# 새 시뮬레이터 — 대량 생성 전 요청 사항 (2026-09-17)

3차분(`AIUE_vol8_01` · 일상 5 + 스캔 1)을 받아 **변환·좌표 검증까지 끝냈습니다.** 스캔이 붙으면서 처음으로 우리 기존 데이터셋(HSSD·OmniGibson)과 **같은 조건으로 전체 파이프라인을 돌릴 수 있게 됐습니다.** 대량 생성에 들어가기 전에 세 가지만 맞추면 됩니다.

## 1. `scenes/` 는 용량 문제가 아닙니다 — 꼭 넣어 주세요

3차분에 `scenes/AIUE_vol8_01/scene_graph.json` 이 빠져 있었습니다(에피소드의 `initial_state.json` 이 `sha256 3eb9476c…` 로 참조만 하고 파일은 없음). 2차분의 같은 장면 파일을 빌려 변환했는데, 그건 **해시가 다른 파일**이라 물체 좌표가 어긋났을 수 있습니다.

용량은 문제가 되지 않습니다.

| | 크기 |
|---|---|
| 2차분 `episodes/` (30 에피소드) | **1.7 GB** |
| 2차분 `scenes/` 전체 (3장면 × 10파일) | **6.2 MB** (0.36%) |
| 장면그래프 1개 | 0.21 MB |
| **우리가 실제로 쓰는 부분(`rooms` 만)** | **0.9 KB** |

**장면당 한 개면 충분합니다.** 2차분은 에피소드마다 한 벌씩 10개를 넣어 주셨는데, 확인해 보니 **10개의 방 기하가 전부 동일**했습니다. 장면당 1개로 줄이면 6.2 MB → 0.6 MB 입니다.

**더 줄이고 싶으시면 `rooms` 배열만 주셔도 됩니다.** 우리가 장면그래프에서 읽는 것은 이 세 가지뿐입니다.

```json
{ "metadata": {"units":"centimeters","up_axis":"Z","coord":"unreal_left_handed"},
  "rooms": [ {"id":"bedroom_1","room_type":"bedroom",
              "rect_xy":{"min":[231.0,-352.0,0],"max":[547.0,164.0,280.0]}}, … ] }
```

`objects`·`relationships`·`cameras` 는 **안 씁니다**(물체 정보는 `annotations.jsonl` 과 `evidence.json` 에서 가져옵니다). 방 경계가 없으면 카메라가 어느 방에 있는지, 답이 어느 방인지를 판정할 수 없어 **평가 자체가 불가능**합니다.

## 2. 질의 대상을 늘려 주세요 — 지금은 에피소드당 3개

현재 `evidence.json` 의 대본 사건 3개(`relocated`/`absent`/`unchanged`)만 질의 대상이 됩니다. 그러면 에피소드 5개에서 **① 5건 · ② 5건 · ③ 5건** 이고, 이 규모로는 어떤 지표도 통계가 서지 않습니다(참고로 지금 HSSD 에서 ② 137건 · ③ 152건으로 결론을 냅니다).

`entities.json` 에는 **queryable 물체가 228개** 있습니다. 이들의 **시작 위치(방)** 만 알면 전부 ① 질의로 쓸 수 있고, 그러면 에피소드당 ① 이 100건 이상 생깁니다. 지금은 `initial_state.json` 의 `relationships` 에 `contains` 가 에이전트 2건뿐이라 물체의 시작 방을 알 수 없습니다.

**요청:** `initial_state.json` 에 **모든 queryable 물체의 `(물체 → 방)` 관계와 월드 좌표**를 넣어 주세요. `ground_truth_updates.jsonl` 의 첫 프레임(t=0)에 `{"op":"relationship","s":<object>,"p":"in","o":<room>}` 을 전부 찍어 주셔도 됩니다.

이게 있어야 **"안 움직인 물체를 움직였다고 오판하는 비율"**(우리 최대 오류원, 현재 HSSD 에서 1.9%)을 새 시뮬레이터에서 잴 수 있습니다.

## 3. 대량 생성 규모 제안

3차분 구조(장면 1개 = 스캔 1 + 일상 N)가 맞습니다. 그대로 늘려 주시면 됩니다.

| | 요청 | 근거 |
|---|---|---|
| 장면 | **5~10개** | 도메인 편중 방지. 2차분이 3개였습니다 |
| 장면당 일상 에피소드 | **10개 이상** | 사건이 에피소드당 3개이므로 장면 10 × 에피소드 10 = ①②③ 각 100건 |
| 장면당 스캔 | **1개** | 3차분과 동일(4,697프레임)이면 충분합니다. 우리는 1초마다 솎아 157장을 씁니다 |
| 사건 구성 | 지금처럼 ①②③ 1개씩 | 균형이 좋습니다 |

예상 용량은 2차분 기준으로 에피소드당 약 55 MB 이니 **장면 10 × 에피소드 10 ≈ 5.5 GB + 스캔 10개**입니다.

## 3차분에서 확인된 것 (좋습니다, 유지해 주세요)

- **영상 정지 버그 없음**: 스캔 4,697프레임 = 주석 4,697행, 일상 에피소드도 전부 일치 (1차분은 7,332 대 9,000 이었습니다)
- **프레임마다 카메라 포즈**: 4,697/4,697 전량. 우리 자체 위치추정 없이도 기하를 검증할 수 있어 매우 유용합니다
- **사건 라벨이 대본에 박혀 있음**: `case` · `source_room`/`destination_room` · `before_window`/`after_window`
- **좌표 규약 확인**: 우리 쪽에서 `x←UE_Y · 높이←UE_Z · z←UE_X` 로 맞췄고 투영 방위 오차 중앙 **3.5°** 입니다 (문서에 축 대응이 없어 전수 탐색으로 찾았습니다 — 다음 배치 `metadata` 에 축 순서를 명시해 주시면 좋겠습니다)
