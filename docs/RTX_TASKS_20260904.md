## 2. SfM 재국소화 (신규) — 위치 GT 를 빼는 첫 후보
배경: 1fps live 스트림을 추적(DA3 체인·SfM 사슬)하는 건 프레임 사이 겹침이 없어 구조적으로 실패했다(HSSD §139).
대신 **매핑워크를 한 번 무겁게 재구성하고 live 프레임을 프레임별로 지도에 등록(재국소화)** 한다. 겹침 불필요.
HSSD 20채판(M1)과 같은 코드·같은 지표로 OG 에서 재는 것이 이 항목이다.

설치:
```bash
pip install pycolmap            # CUDA 휠. import pycolmap; pycolmap.Device.cuda 확인
mkdir -p ~/khcache/colmap && curl -L -o ~/khcache/colmap/vocab_tree_faiss_flickr100K_words32K.bin https://github.com/colmap/colmap/releases/download/3.11.1/vocab_tree_faiss_flickr100K_words32K.bin
```
실행(채마다 1회, GPU 면 수 분):
```bash
python scripts/sfm_reloc.py data/og20/<house> --gpu --threads 8 --out ~/khcache/sfm/pose_<house>.jsonl
```
입력 요건(og_episode 출력이 이미 이 형식이어야 한다 — 아니면 먼저 맞출 것):
- `map/%04d.jpg` ↔ `gt.json["map"][i]` (`apos=[x,z]`, `yaw`, `room`) 순서 일치. `live/%06d.jpg` ↔ `gt.json["live"]` 의 `t`.
- 핀홀 hfov 90° 정사각(`fx = W/2`). 다르면 sfm_reloc.py 의 fx 계산을 카메라 정보로 바꿀 것.
- `gt.json["rooms"]` 폴리곤(`[x,z]` 목록) — 카메라방 적중 계산에 쓴다. 없으면 그 칸만 "—".

**매핑워크 요건 추가 (SPEC 3-b)**: 지점에서 45° 씩 도는 프레임만으론 SfM 이 초기화되지 않는다(순수 회전엔 시차가 없다).
**지점 사이를 걷는 동안의 프레임을 0.3m 간격으로 기록**하라(2fps 상당). 매핑워크는 무거워도 된다는 합의 그대로.

보고(채별 한 줄 + 합계): `map 등록/전체 · live 커버리지 · ATE 중앙(m) · <0.5m 비율 · yaw 오차 중앙(°) · 카메라방 적중 · 소요(s)`
(= `~/khcache/sfm/<house>/summary_<house>.json` 의 값). 합격선(HSSD 결과와 나란히 볼 것): 커버리지 ≥0.7 · ATE 중앙 ≤0.5m · 카메라방 적중 ≥0.9.

**알려진 실패 모드 — 유령 복제**: 반복 가구·대칭 구조에서 집 일부가 두 번 재구성돼 프레임 40% 가 10m 떨어진 사본에 붙는다.
연속 20~50프레임이 통째로 튀므로 속도 필터(`--vmax 2.5`, GT 불필요)로는 일부만 걸러진다. 대응 순서: `--strict`(PnP 문턱 강화)
→ 매핑워크에 이동 프레임(SPEC 3-b) → 그래도 남으면 채 이름·프레임 구간을 보고. OG 는 자산이 HSSD 보다 다양하니 덜할 것으로 본다.

**실행(권장 플래그)**: 채별 병렬 러너가 있다.
```bash
ROOT=data/og20 HOUSES=4 PAR=2 THREADS=8 EXTRA="--gpu --fast --vmax 2.5" bash scripts/sfm_batch.sh
```
**척도 (2026-09-04 추가)**: `--scale da` 는 단안 메트릭 깊이(DA-V2)로 척도를 잡아 정렬용 GT 에서 척도를 뺀다(HSSD §146:
GT/DA 상수 0.468±5%). OG 렌더러는 상수가 다르니 **1채에서 먼저 재보정**: `python scripts/sfm_scale_da.py data/og20 <house>`
가 찍는 `GT/DA` 를 `--da-k` 로 넘긴다. 이후 4채·20채는 `EXTRA="--gpu --fast --vmax 2.5 --scale da --da-k <값> --align sites"`.
`--align sites` 는 GT 좌표 없이 정렬한다(§148): gt.json 에 `scene_meta.polys`(방 폴리곤 [x,z])와 `map[i].room`(지점 라벨)이 있어야 한다.
채별 표와 합계가 찍힌다(`SFM_BATCH_DONE`). CPU 4스레드 M1 에서 채당 15~23분(SIFT 3.5분·live 등록 10~17분)이었으니
CUDA 에선 수 분이어야 한다. `--fast` 는 전역 BA 를 덜 돌린다 — 4채에서 `--fast` 유무의 ATE 차이를 한 줄로 같이 보고.

### 2-c. 최신 단안 SLAM 대조 (RTX 전용 — CUDA 필요, M1 불가) — §2 COLMAP 과 같은 4채·같은 지표
COLMAP SfM 은 옛 방식이다. 최신 단안 SLAM 이 우리 자리(매핑 1회 + live 프레임별 재국소화)에서 더 나은지 **같은 4채, 같은
표**로 대조한다. 후보 둘, 우선순위 순:
1. **MASt3R-SLAM** (github.com/rmurai0610/MASt3R-SLAM): 학습 매칭이라 무텍스처 벽에 강하고 **메트릭 척도가 바로 나온다**
   (DA 상수 보정 불필요). 재국소화(retrieval + 2-view) 모드가 있어 1fps live 를 프레임별로 붙일 수 있다.
2. **DA3 any-view**(depth-anything-3, 이미 설치돼 있으면): 매핑워크 전체를 한 번에 넣어 포즈+깊이를 피드포워드로.
   live 는 map 키프레임에 대한 2-view 로 붙인다.
절차: map/(+SPEC 3-b 이동 프레임) 으로 지도 → live/%06d.jpg 프레임별 재국소화 → 프레임마다 c2w 4×4 를 한 줄(16값)로
`pose/poses_<method>.txt` 에 쓰고(어댑터 `scripts/hssd_to_seq.py` 형식), `python scripts/pose_eval_hssd.py <seq> <house> --pose
pose/poses_<method>.txt --out pose_<house>_<method>.jsonl` 로 같은 지표(커버리지·ATE·yaw)와 POSE_JSONL 을 얻는다.
보고: §2 COLMAP 행 바로 아래에 method 행을 붙인 표 하나(채별 커버리지·ATE 중앙·<0.5m·yaw·카메라방·채당 시간).
판정 기준: 커버리지와 유령 복제(ATE 평균 ≫ 중앙)에서 COLMAP 을 이기면 OG 쪽 기본으로 채택. 지지 않으면 COLMAP 유지.
ORB-SLAM3 같은 고전 특징점 SLAM 은 COLMAP 과 같은 계열이라 대조 가치가 없다 — 하지 말 것.
