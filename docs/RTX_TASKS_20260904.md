## 2. SfM 재국소화 (신규) — 위치 GT 를 빼는 첫 후보
배경: 1fps live 스트림을 추적(DA3 체인·SfM 사슬)하는 건 프레임 사이 겹침이 없어 구조적으로 실패했다(HSSD §139).
대신 **매핑워크를 한 번 무겁게 재구성하고 live 프레임을 프레임별로 지도에 등록(재국소화)** 한다. 겹침 불필요.
HSSD 20채판(M1)과 같은 코드·같은 지표로 OG 에서 재는 것이 이 항목이다.

설치:
```bash
pip install pycolmap            # CUDA 휠. import pycolmap; pycolmap.Device.cuda 확인
mkdir -p ~/khcache/colmap && curl -L -o ~/khcache/colmap/vocab_tree_faiss_flickr100K_words32K.bin https://github.com/colmap/colmap/releases/download/3.11.1/vocab_tree_faiss_flickr100K_words32K.bin
```
실행(채마다 1회, GPU 면 수 분):
```bash
python scripts/sfm_reloc.py data/og20/<house> --gpu --threads 8 --out ~/khcache/sfm/pose_<house>.jsonl
```
입력 요건(og_episode 출력이 이미 이 형식이어야 한다 — 아니면 먼저 맞출 것):
- `map/%04d.jpg` ↔ `gt.json["map"][i]` (`apos=[x,z]`, `yaw`, `room`) 순서 일치. `live/%06d.jpg` ↔ `gt.json["live"]` 의 `t`.
- 핀홀 hfov 90° 정사각(`fx = W/2`). 다르면 sfm_reloc.py 의 fx 계산을 카메라 정보로 바꿀 것.
- `gt.json["rooms"]` 폴리곤(`[x,z]` 목록) — 카메라방 적중 계산에 쓴다. 없으면 그 칸만 "—".

**매핑워크 요건 추가 (SPEC 3-b)**: 지점에서 45° 씩 도는 프레임만으론 SfM 이 초기화되지 않는다(순수 회전엔 시차가 없다).
**지점 사이를 걷는 동안의 프레임을 0.3m 간격으로 기록**하라(2fps 상당). 매핑워크는 무거워도 된다는 합의 그대로.

보고(채별 한 줄 + 합계): `map 등록/전체 · live 커버리지 · ATE 중앙(m) · <0.5m 비율 · yaw 오차 중앙(°) · 카메라방 적중 · 소요(s)`
(= `~/khcache/sfm/<house>/summary_<house>.json` 의 값). 합격선(HSSD 결과와 나란히 볼 것): 커버리지 ≥0.7 · ATE 중앙 ≤0.5m · 카메라방 적중 ≥0.9.
