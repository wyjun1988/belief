# 평가 프로토콜 v2 — 증거 조건부 (2026-09-02)

사용자 지적: "시나리오에 따라 달라지는 수치가 재검 능력을 제대로 평가하는 게 맞나."
맞지 않았다. ② 정답률은 **시나리오가 이동 후 목격을 몇 번 만들어줬는지**에 지배되고
(bench-v2: k=0 → 0, k=6+ → 진짜 채택 1.00), 같은 시스템이 표본 14건의 목격 분포에
따라 0.36~0.43 사이를 오갔다. 스칼라 ② 는 능력이 아니라 시나리오를 잰다.

## ② 는 곡선으로 보고한다 (eval_online 자동 출력)
| 항목 | 뜻 | 시나리오 의존 |
|---|---|---|
| 진짜 목격 프레임 검증 통과율 (거리별) | 지각 능력: 보이는 물체를 받아들이는가 | 없음 |
| 오채택 수 (물체 없는 후보 통과) | 정밀도: 없는 것을 받아들이는가 | 없음 |
| k=0 행의 c0 발동 | **거짓 인계율** — 0 이어야 한다 | 없음 |
| k 별 진짜채택≥1 | 증거 k 개가 있을 때 하나라도 잡는가 | k 로 조건화 |
| **k=6+ 행의 정답률** | 증거가 충분할 때 **판정·국소화** 능력 | k 로 조건화 |
| 시나리오 ② 정답률 | = 위 곡선 × 그 시나리오의 k 분포 | **있음** (참고) |

bench-v2 첫 곡선: 통과율 <2m 0.50 · 2-5m 0.59 · 5m+ 0.17 / 오채택 12.7장 per 100 /
k=0 거짓 인계 0 / k=6+ 진짜채택 1.00 · **정답 0.50**. → 증거 다음 병목은 채택 이후의
판정·국소화이며, 이는 데이터가 아니라 알고리즘 문제다.

## 증거량을 통제 변수로 (생성기 `--evidence K:D`)
②의 능력 곡선을 시나리오 우연에 맡기지 않는다. 이동(② 역할) 후 궤적이 **거리 D 에서
시선이 닿는 지점을 K 번 들르도록** 목적지를 심는다(연속 보행 유지 — 텔레포트 아님).
같은 집에서 K∈{1,2,4,8}, D∈{1.5,3,5} 격자를 돌리면 곡선이 직접 나온다.
③ 은 종전대로 대본(목적지 방 제외 + 시선 누출 경로 재추첨) — k=0 의 통제군이기도 하다.

## 보고 규칙
- ② 를 한 숫자로 쓰지 않는다. 곡선 표 + 시나리오 k 분포를 같이 쓴다.
- 알고리즘 비교는 **같은 k 행끼리** 한다 (예: C0_MIN 1 vs 2 는 k=6+ 행의 정답률로).

## 보고 형식 (2026-09-03 사용자 확정) — 진행 점검은 항상 두 표
1. **모듈별 성능표**: 항목 · 기술 · 성능 · 의미. 관측(검출·검색·검증·재식별) / 위치(yaw·거리·물체→방·카메라방) /
   씬그래프(초기맵·재관측 채택·부재) / 전체. 재료 사다리 병기.
2. **3+1 전체 성능표**: ① 정답률 · ② 정답률(+c0 발동/채택정답) · ③-1 인계율 · ③-2 무인계 준수 · ④ 정답률 ·
   전체 top-1 · 기준선(초기맵만·사전확률만) · n·CI. 기존 → 현재.
