## 3. 확정된 사실 (되풀이 금지)
1. **무GT 사슬은 돈다. 점수가 무너질 뿐이다.** 30채 무GT: 전체 0.131 · ① 0.137 (GT 포즈판 0.673 / 0.720, 사전확률 기준선 0.635). §163
2. **원인은 국소화 하나다.** COLMAP 이 30채 중 1채만 세웠다.
3. **밀도는 필요조건이나 충분조건이 아니다.** 지도 46→391장에서 house_0001 만 살아남(인라이어 0.00→0.84). §164
4. **실패는 척도가 아니라 접힘이다.** GT sim3 로 척도까지 풀어도 인라이어 0.05~0.17. §164 후속
5. **순차 전용 매칭(`--matcher seq`)은 더 나쁘다.** 드리프트 누적(ATE 3.83→11.35m). §164 후속
6. **joint 가 지도를 오염시킨 게 아니다.** `--map-only` 정렬도 같은 값(0.08/0.85/0.17/0.05). 지도 단독 재구성 자체가 접혔다(등록 374/383·재투영 0.27px 인데도).
7. **코드는 무죄다.** 지금 코드로 옛 데이터를 돌리면 그대로 선다 — 옛 house_0000 지점정렬 **70/70**·ATE 0.10m·카메라방 0.98 / 옛 house_0002 **97/105**·0.04m·0.94.
8. **걷기 사실성도 범인이 아니다.** 옛 걷기(정지 0.00·313m)로 새 장면을 다시 만들어도 실패 — 지점정렬 0.34~0.39·ATE 2.4~4.7m·카메라방 0.21~0.39.
9. **좌표 없는 방판정(검색)은 지금 형태로는 못 쓴다.** 매핑워크 방 프로파일 코사인 최근접 = GT 일치 **0.217**(우연 수준). `scripts/room_retrieval.py`

## 4. 가장 유력한 미검증 가설 — 촘촘한 지도가 오히려 접힘을 만든다
옛 성공판의 로그를 보면 **map 단독 등록이 7/128, 7/184 로 빈약해서 joint 로 폴백**했고, 그 joint 를 **라이브 보행이 이끌었다**.
새 판은 반대다. 촘촘한 지도가 map 단독으로 374/383 을 등록해 `map_ok=True` 가 되고, 그 **접힌 모델이 joint 의 씨앗(`input_path`)이 되며
`fix_existing_frames=True` 로 고정**된다. 즉 접힌 지도가 라이브까지 끌고 간다.

**검증 방법**: `sfm_reloc` 에 "지도 씨앗 없이 joint 처음부터" 경로를 추가해(`map_ok` 를 강제로 False) 같은 4채를 다시 정렬.
`~/khcache/sfm-dense` 의 DB(특징·매칭)는 재사용되므로 재구성만 다시 하면 된다(`--redo-map` 은 rec_* 만 지운다).
이게 서면 처방은 "지도는 성기게, joint 는 라이브가 이끌게" 이고, 촘촘한 매핑워크는 되돌린다.

**두 번째 미검증 축**: 장면 차이. 옛 성공은 `docs/bench/hssd20_scenes.txt`, 새 실패는 `hssd40c_scenes.txt` — **다른 집들**이다.
`data/hssd20_c3`(같은 장면·새 대본·촘촘한 지도)에 SfM 을 돌리면 장면과 지도/걷기를 가를 수 있다.

### 9-1. 가장 유력한 수 — 지도 씨앗 없이 joint 처음부터 (§4 1번)

```python

map_ok = rm is not None and rm.num_reg_images() >= max(10, 0.3 * len(maps))
if os.environ.get("NO_MAP_SEED") == "1": map_ok = False   # 접힌 지도가 joint 씨앗이 되는 것을 막는다
```
그다음(DB·특징은 재사용, 재구성만 다시):
```bash
cd ~/work/khronos
for i in 0000 0001 0002 0003; do
  NO_MAP_SEED=1 KMP_DUPLICATE_LIB_OK=TRUE ~/kx-venv/bin/python -u scripts/sfm_reloc.py \
    data/hssd40_c3/house_$i --redo-map --align sites --scale da --fast --features 4096 --threads 4 \
    --work ~/khcache/sfm-noseed/house_$i --out ~/khcache/sfm-noseed/pose_house_$i.jsonl 2>&1 \
    | grep -aE "map 재구성|라벨 정렬|커버리지"
done
```
판정선: **지점 정렬 ≥0.9 · 카메라방 ≥0.8**. 현재값은 0.34~0.39 · 0.21~0.39.
⚠️ `--redo-map` 은 반드시 **기존 `--work`** 에 써야 DB 를 재사용한다(새 디렉터리면 SIFT 부터 다시 = 4시간 낭비).
