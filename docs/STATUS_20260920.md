### `stand` 는 어휘 문제였다 (§166-94, **파일럿 진행 중**)
- HSSD 시맨틱 사전에 `stand` · `nightstand` · `tv_stand` 가 별개 카테고리. 우리 `stand` 33채의 GT 물체는 **31채가 TV 장**.
- OWL 에 현재 프롬프트로 물으면 GT 물체 점수 중앙 0.160(≥0.2 비율 0.36). **"tv stand" 면 0.371(0.70)**, 딴 곳 점수는 0.099.
- 처방: 타입 키는 `stand` 그대로(조인 유지), **OWL·제로샷 프롬프트 문장만** "tv stand" 로 — `data/owl_alias.json` + `scripts/owl_alias.py`. 학습된 LoRA 판정기 프롬프트에는 적용하지 않는다(학습 분포 보존).
- 검증 설계: 옛 초기맵 / 같은 명령으로 재군집한 것(재현성) / 별칭 캐시로 새로 만든 것 — 세 팔을 같은 33채·같은 조건으로.
- 다른 타입은 별칭 불필요 — 움직이는 9개 타입 전부 재니 질의어가 GT 에 안 붙는 건 `stand` 하나.

### `floor lamp` 는 구조 문제
질의어는 GT 에 잘 붙는다(0.549 vs 딴곳 0.151). 천장등·탁상등에 대한 **약한 검출이 여러 프레임에 쌓여** 가짜 군집의 합산 가중이 커진다. 문턱을 올리면 floor lamp 0.705→0.727 이 되지만 ② 가 0.416→0.394 로 떨어진다 — ② 가 초기맵 후보를 참조 크롭으로 쓰기 때문. **기록용 지도와 참조용 지도를 분리**하면 둘 다 취할 수 있다(미구현, 이득 +0.014).

### ③ 은 ① 과 같은 벽
c3big: 기록 자리 오차 ≤1 m 면 인계 0.73, >3 m 면 0.31. 4차분: GT 자리로는 7/10 이 확인기회를 얻는데 초기맵 자리로는 3/10. → **초기맵 인스턴스 선택이 ①③ 공통 병목**.

### 4차분(새 시뮬레이터)에서만 먹힌 것
기록자리 판정기 `PLACE_W=2`: ① 0.576→**0.722**, ③ 확인기회 1→4건. HSSD 에선 개선 4·퇴행 4 로 상쇄. **기준선(정답 후보가 1등인 비율)이 0.6 미만일 때만 켠다** — HSSD 0.727 · c3big 0.768 (끔) / 4차분 0.486 (켬).

## 5. 이번 주말 잡은 함정 (재발 방지)
- 스윕 결과가 소수점까지 같으면 배선을 의심 — exemplar 캐시 없음 → 인스턴스 노브 통째 무시.
- `scene_meta.static` 없으면 벤치가 **종료코드 0·빈 행**으로 끝난다.
- 데이터셋별 사전확률 표(이동성)를 다른 데이터셋에 그대로 쓰면 0 처리 → 절반 넘게 걸러지면 경고 추가.
- 벤치 재료 스크립트는 스크래치패드에 두지 않는다(유실).
- 중간 지표(라벨 정확도 0.741) 가 좋아져도 최종 지표에서 상쇄될 수 있다 — 반드시 벤치·두 데이터셋으로 확인.
