사용자 진단: "계속 문제를 못 해결하고 있다". **절반 맞다.** 부품은 크게 좋아졌고
그 근거도 명확한데, **제품 지표(3경우)는 두 달째 제자리**다. 왜인지 정직하게 적는다.

## 3. 왜 반복되는가 — 세 가지 구조적 원인

### (a) ②의 병목은 검증도 검색도 아니고 "후보에 진짜가 없음"(A율)
- THOR A=15%(깊이80) / HSSD A=57~84%
- 즉 **이동 후 목격 프레임이 상위 후보에 안 들어온다**. 검증기를 아무리 고쳐도
  (s_ac·박스크롭·문턱 5종 격자, §112-118) 이득이 +1~2%p 에 그친 이유가 이것.
- **한 번도 정면으로 공략하지 않았다** — 검색 랭킹(TS = 이미지질의 + 글자질의)의
  시간 가중·재질의·2차 검색이 미개척.

### (b) ③은 시뮬에서 "희귀 사건"이다
- THOR: 강제 240건 → 유효 4건(2%). HSSD: 21 → 13 → 16건.
- 이동 후 **한 번도 안 보이면서 옛 방은 재방문**하는 조합이 자연 발생하지 않는다.
- 매번 생성 파라미터를 바꿔 표본을 늘리려 했지만(case3·far·에피소드 길이)
  근본은 **무작위 배회로는 특정 사건을 보장할 수 없다**는 것.

### (c) 도메인 이식마다 인프라 부채를 갚느라 알고리즘 개선을 못 한다
- ReplicaCAD·HSSD 이식에서 고친 것: 좌표 규약 2단계, 매핑워크, 이동 GT 31% 오염,
  navmesh, 시맨틱 부재, 라벨 위생, 타입 단일 부재, exemplar 누락, 시나리오 사전확률…
- 전부 **필요한 수정**이었지만, 그 사이 ②③ 알고리즘은 한 줄도 안 바뀌었다.

## 4. 전환 제안 (다음 2주)

### 제안 1: 시나리오를 **결정론적으로 설계**한다 (무작위 생성 중단)
지금은 배회·이동을 확률로 굴리고 사후에 "몇 건 나왔나" 를 센다. 대신 **각 경우를
정확히 N건씩 대본으로 박는다**:
- 경우① 30건: 안 움직임 + 재방문 O
- 경우② 30건: 이동 → 새 방에서 근거리 재목격 **보장**(궤적을 그 방에 보냄)
- 경우③ 30건: 이동 → 새 방 **미방문** + 옛 방 재방문 **보장**
- 경우④ 15건: 집 밖 반출
그러면 표본 부족이 사라지고, 지표가 도메인 우연에 안 흔들린다.

### 제안 2: ② 의 A율을 정면 공략 (알고리즘)
- 시간 가중 검색(최근 프레임 우대) · 채택 프레임 되먹임 재질의 · 방별 2차 검색
- 목표: A 57% → 25% 이하. 이게 ② 0.176 → 0.35+ 의 유일한 경로.

### 제안 3: 도메인 고정
OmniGibson(BEHAVIOR)으로 확정하고 **더 옮기지 않는다**. 이식 부채를 한 번만 갚고
그 위에서 알고리즘을 반복한다. THOR 는 무GT 대조군으로만 유지.
