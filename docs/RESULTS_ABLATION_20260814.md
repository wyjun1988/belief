## 결론 셋

### 1. 절벽은 depth 가 아니라 pose 에 있다

depth 만 DA3 로 바꾸면(A→B) 위치오차가 0.066 → 0.162 m 로 2.5배 늘지만 방 단위 판단은
0.987 로 버틴다. 대신 **정밀도가 1.00 → 0.44** 로 떨어진다 — 큰 정적 가구가 시점에 따라
"움직였다"고 잡히기 시작한다.

pose 까지 바꾸면(B→C) 위치오차 1.482 m, **이동 감지 재현율 0.00**, home-jepa top1 0.161.
*어느 방*인지는 0.751 로 절반 넘게 맞지만 *어느 가구 위*인지는 무너진다.
**방 단위(3–5 m)와 가구 단위(0.5–1.5 m)를 가르는 선이 여기다.**

뎁스 정합(T2 앵커 + T3 시간 정칙화)의 효과는 AbsRel 이 아니라 **정적 물체 3D 산포
0.138 → 0.086 m (−40%)** 에 나타난다. 맵이 덜 "숨쉬는" 것이 씬그래프가 가짜 변화를 안
만드는 조건이다.

### 2. 구역 시드의 GT 의존은 제거된다 — 비용 거의 0, 단 방법 선택이 중요하다

D→G 는 **시드 출처만** 다른 통제된 비교다: home-jepa top1 0.775 → **0.776**, 방 0.866 → **0.869**.

방법을 잘못 고르면 대표 질문이 깨진다:

| 시드 출처 | 침실 | 부엌/다이닝 | 액자 체인 |
|---|---|---|---|
| **물체 단위 CLIP** (F) | ✗ 시드 0개 | ✓ 냉장고·식탁의자 | **부엌**→거실 ✗ |
| **프레임 단위 CLIP** (G) | ✓ 156프레임 | ✗ kitchen 이 459프레임 중 1위 **2회** | 침실→거실→거실 ✓ |
| **둘을 합침** (H) | ✓ | ✓ | 침실→거실→거실 ✓ |

- 물체 단위가 침실에서 막힌 이유: FastSAM 은 침대를 통째로 잡지 않고 **매트리스 표면 조각**을
  준다. 천 표면 클로즈업은 CLIP 한테 베개와 구별되지 않는다(`BlackBedFrame → 최강방해 "a pillow"`).
  침실 시드가 0개가 되자 인접한 가짜 kitchen 시드(`Thermostat → microwave`)가 그 공간을 삼켰다.
- 프레임 단위가 개방공간에서 막힌 이유: 벽이 없어 어느 시점에서 찍어도 프레임 안에 거실 가구가
  같이 들어온다. **프레임 하나에 방 하나를 배정하는 방식 자체가 개방공간에 안 맞는다.**
- 두 실패가 상보적이라 **손으로 고르지 않고 그냥 합치면** 서로 메운다. H 의 ARI 0.389 는
  GT 시드(0.409)에 근접하고, 침실·부엌·다이닝이 모두 살아난다.

### 3. 카테고리의 GT 의존도 제거된다 — 질의 방식을 바꾸면

H 에서 home-jepa 물체가 61 → 1개로 떨어진 것은 **지각 실패가 아니라 어휘 사상 실패**다.
그래프에는 액자가 21개 트랙으로 살아 있고, 그중 하나는 439회 관측 · 침실→거실→거실 체인
전체를 들고 있다(`category: null` 일 뿐).

고정 어휘를 우회해 **그래프에 직접 질의**하면:

| 재식별 방법 | D (GT 카테고리) | **H (지각 GT-free)** | 후보 수 | 위치오차 |
|---|---|---|---|---|
| GT 인스턴스로 묶기 (상한) | 0.973 | 0.959 | 11 | 0.16 m |
| **CLIP 외형 코사인 ≥ 0.95** | 0.958 | **0.958** | 4 | 0.19 m |
| CLIP 외형 ≥ 0.90 (너무 느슨) | 0.816 | 0.816 | 246 | 2.2 m |

**지각 GT-free 구성이 GT 카테고리 구성과 소수점까지 같다** (단 둘 다 기하는 GT).
GT 는 "이 물건 어디 있어?" 라는 **질문을 지목하는 데만** 쓴다(사용자가 물건을 한 번 보여주는
상황). 답을 고를 때는 임베딩 유사도만 본다 — 카테고리도 GT id 도 보지 않는다.

**남은 GT 축은 pose·depth 하나뿐이고**, 그마저 방 단위 질문에서는 0.825 까지 간다(party 기준).

## 구성요소 — 무엇이고 무엇을 푸는가

GT 마스크는 공짜로 **네 가지**를 주고 있었다. 그것을 넷으로 쪼개 대체한 구조다.

| GT 가 주던 것 | 대체 | 상태 |
|---|---|---|
| ① 마스크 | **FastSAM** | ✓ (과분할 대가: 노드 213 → 598) |
| ② 프레임 간 연관 | **BotSort + CLIP ReID** | ✓ |
| ③ 구역 시드 카테고리 | **프레임+물체 CLIP 제로샷** | ✓ (합쳐야 됨) |
| ④ 물체 카테고리 | **CLIP 외형 재식별로 우회** | ✓ (고정 어휘는 포기) |

**FastSAM** — YOLOv8-seg 백본, SA-1B 의 2% 로 학습한 "전부 분할" 모델. SAM 대비 ~50× 빠르다.
→ 푼다: 이 프레임 어디에 물체 덩어리가 있는지, 픽셀 단위로.
→ 못 푼다: 그게 **무엇인지**(class-agnostic), 다음 프레임의 어느 마스크와 **같은 물체인지**.
　 과분할이 심해 노드가 213 → 598 로 늘어난다.

**BotSort** — 다중객체 추적기. 칼만 운동 예측 + **카메라 운동 보상(CMC)** + IoU/외형 결합 매칭.
→ 푼다: 프레임 간 연관 → track id. 착용자 머리가 계속 움직이는 Aria 영상에서 CMC 가 특히 중요하다.
→ 못 푼다: 긴 가림, 방을 나갔다 돌아오는 경우 → 조각이 끊긴다.

**CLIP ReID** — 마스크마다 CLIP 이미지 임베딩(ViT-B/16)을 뽑아 BotSort 의 **외형 항**으로 쓴다.
→ 푼다: 가림 뒤 재등장 매칭. 운동 예측이 끊긴 자리를 "생김새가 같다"로 잇는다.
→ 못 푼다: 똑같이 생긴 물체 여러 개(같은 의자 4개).

**CLIP 제로샷 (물체 단위)** — 마스크 크롭 임베딩을 라벨 텍스트 임베딩과 코사인 비교.
방해 라벨(wall, floor, curtain, pillow…)을 같이 넣고 마진을 넘어야 채택.
→ 푼다: 큰 가구(냉장고·식탁의자)의 카테고리 → 개방공간 구역 시드.
→ 못 푼다: 부분 크롭으로 나오는 침대류, 그리고 소물체 전반.

**CLIP 제로샷 (프레임 단위)** — 프레임 전체를 "a bedroom / a kitchen / …" 로 분류하고,
시간 다수결을 통과한 라벨을 **카메라 앞 1.6 m 지점**에 시드로 찍는다(관찰자 위치를 쓰면
문간에서 옆방을 들여다볼 때 라벨이 자기 방에 찍힌다).
→ 푼다: 벽으로 갈린 방(침실).
→ 못 푼다: 벽 없는 개방공간(부엌 459프레임 중 1위 2회).

## 단서 (이 숫자를 읽을 때)

1. **home-jepa belief 층의 값어치는 이 데이터로 측정되지 않는다.** 모든 구성에서 모델 top1 이
   last-known 베이스라인과 소수점까지 같다(`stayed` 1.000 / `moved` 0.000). ADT 에는 미관측
   이동이 없기 때문이다 — 착용자가 직접 옮기므로 모든 이동이 시야 안에서 일어난다.
   재려면 "안 보는 사이에 누가 옮기는" 데이터가 필요하다.
2. **액자는 home-jepa 어휘에 없다.** 그 모델의 24클래스는 개인 소지품(열쇠·지갑·전화…)이고
   `wall artwork` 는 규칙조차 없다. home-jepa 열은 `wall artwork=book` 으로 **억지 사상**한 결과다.
3. **belief 타겟은 전부 소물체다.** 실제로 움직인 물체의 최대변: decoration 0.10–0.51 m,
   party 0.09–0.80 m (11개 중 10개가 0.5 m 미만, 중앙값 0.16 m). "가구 단위로만 답하면 된다"면
   파이프라인은 이미 GT 없이 돈다. 소물체가 타겟이면 ④의 우회(외형 재식별)가 필수다.
4. **표본이 작다.** decoration 의 동적 물체 4개 · 방 바뀐 질의 7개, party 는 7개 · 57개.
   소수 셋째 자리를 신뢰하지 말 것.
5. **"누가 옮겼나"는 뺐다.** 착용자 시점만으로는 행위자 귀속의 정답을 만들 수 없다.
6. **Khronos + DAAAM + Hydra 는 대조군으로 한 번만 돌렸다**(562노드 DSG, ROOMS=2 — 침실을
   못 갈라냄). 위 표의 그래프는 전부 우리 4D 빌더(`kx/graph/build.py`)가 만든 것이고,
   DAAAM 에서 가져다 쓴 것은 **세그멘테이션·추적 프론트엔드**이지 그래프 백엔드가 아니다.
