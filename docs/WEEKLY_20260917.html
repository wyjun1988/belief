§4LLM·LoRA 에서 확정한 것

  • 라벨이 공짜다. 시뮬레이터 GT 로 채택 4,791 · 부재 2,967 · 기록자리 7,566 · ②중심 채택 2,948 표본을 사람 손 없이 만들었다. 이게 LoRA 를 가능하게 한 조건이다.
  • 작은 모델 + 적응 > 큰 모델. 채택은 4B = 9B(실측 6,996장), 부재는 4B LoRA > 27B 무학습. 셋 다 4B 로 M2 에서 돈다 — 채택 질의당 9초(상위 8장), 부재 0.7초.
  • 판정은 생성 토큰이 아니라 yes/no 로그확률 차이로 읽는다. 연속값이라 문턱을 최종 점수 기준으로 고른다. 이걸 안 하던 동안 ROC 위 한 점에 묶여 있었다.
  • 도메인은 섞는 게 맞다. OG 를 섞으면 OG +.077, HSSD 도 +.010.
  • 기록 자리는 LoRA 로 안 풀린다. narrow/llm/full(비전 포함)/9B 가 전부 AUC .81. 한계는 적응 용량이 아니라 "참조 없이 크롭 한 장" 이라는 문제 설정이다.
  • 참조를 실제로 본다. 채택 판정기의 참조를 바꿔치기하면 AUC .917 → .777, 마진 중앙 2.0 이동. 다만 참조 없이도 .777 이라 절반은 타입 검출기다.

§6측정을 바로잡은 것 — 조용히 틀리던 열 가지

이번 주 시간의 절반은 여기 들어갔다. 전부 에러 없이 그럴듯한 숫자를 내던 종류다.

  • 검증기가 GT 이동 물체만 채점 → ① 거짓 채택이 공짜 0 (0.737 무효)
  • 임베딩 캐시·지도점·seq 디렉터리가 집 이름만으로 키 → 133채 중 88채가 남의 카메라방 (0.26 vs 0.80)
  • val 채점이 앞 300행 = 25채 중 9채 → 보고된 LoRA 수치 전부 재채점
  • 검증기 점수의 첫 값이 프레임 시각이 아니라 앵커 색인 → "앞단에 신호가 없다" 결론 철회(§166-62)
  • 기록자리 판정이 후보의 34%에만 붙음 → 등록부 전량 등록으로 91%
  • 사슬 방 그룹 단계의 OFFSET 기본값 31 → c2set·c3big 방 그룹이 다른 장면으로 계산(39개 중 38개 달랐음)
  • 트레이너 parse_args 가 편집 중 주석으로 밀림 → HEAD 가 즉사, grep 필터에 가려 세 번 못 봄
  • HSSD 장면 0 은 자산 결함으로 항상 abort → "환경이 깨졌다" 로 오진
  • Habitat STATIC 물체는 translation 무시 → 제거 모드가 물체를 원위치에 둔 채 "가시"
  • MPS 가 크롭 모양마다 재컴파일 + 고아 프로세스 → 판정 속도 3.75배 저하
